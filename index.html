Skill：从"做一次"到"自动跑"

不是展示"AI 能做什么"——而是展示如何将 AI 能力固化为可复用、可自动运行的标准化流程

阶段数据输入处理输出差异化
L1 单次对话处理 手动上传文件 AI 对话分析 生成报告 任何 AI 工具都能做
L2 Skill 固化 指定文件 / 目录 标准化流程 一句话 → 标准输出 做过一次不再教，任何人都能用
L3 跨系统编排 连接器 → ERP / 业务系统 / OA 多源合并 + 异常检测 报告 + 自动上传 + 邮件发送 Skill + 连接器 = 端到端自动化
L4 全自动运行 定时自动触发 自动执行全流程 人不用动，结果自动到位 Schedule + 本地安全闭环

怎么落地

从装客户端到跑通第一个场景的四步，以及把技能装进 Quick Desktop 的具体操作。

1

装客户端

macOS 需 12 (Monterey) 以上且为 Apple Silicon；Windows 需 10 (64 位) 以上。均需 8GB 内存，安装占 500MB，建议再留 10GB 给索引与知识图谱。

2

登录与连数据

企业版选 Continue with SSO；随后按引导连邮件、日历、IM，并授权技能要读写的本地文件夹。

3

配权限、试技能

按最小必要原则设工具权限（写操作先用 Ask Each Time），再导入一个依赖少的技能，用样例数据跑通全流程。

4

沉淀与自动化

把稳定下来的流程存成技能，挂上定时任务，在 Mission Control 里观察运行质量并迭代。

① 导入

左侧导航 Agents & skills → Skills → + Create → Import from file，选择对应的 SKILL.md。导入后出现在 MY SKILLS 分组。

② 配齐依赖

在 Settings → Capabilities → Connectors 授权技能声明的连接器；在 Settings → My computer 授权要读写的文件夹；确认所需系统工具已启用。

③ 三种调用方式

对话里点名技能、让 Quick 按触发词自动识别，或在 Skills 列表点 Run 开一个已载入该技能的会话。

支持的身份提供商

协议层面支持任何兼容 OIDC 的 IdP。官方为 Microsoft Entra ID、Google Workspace、Okta、Ping Identity（PingFederate / PingOne）提供了分步文档；其余 IdP（如 Keycloak）走通用 OIDC 路径，思路一致。账户侧身份类型不限：IAM Identity Center、IAM Federation、Quick 原生用户均可。

强制走企业 SSO

用 MDM 下发 DisableSocialLogin 策略，隐藏社交登录入口并在服务端拦截，使企业 SSO 成为唯一登录路径。

# macOS 偏好域
com.aws.QuickWork.mac → DisableSocialLogin = true

# Windows 注册表
HKLM\SOFTWARE\Policies\Amazon\Quick
  DisableSocialLogin (REG_DWORD) = 1
IdP 中的邮箱地址必须与 Amazon Quick 里该用户的邮箱精确匹配，否则映射失败。受限网络下还需把 Quick 与 IdP 域名加入允许列表。应用会自动沿用操作系统的代理配置，无需单独设置。
