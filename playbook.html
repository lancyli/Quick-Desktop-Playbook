01 · What it is

Quick Desktop 是什么

它是 Amazon Quick 的原生桌面应用，把 Quick 的能力延伸到你的机器上 —— 对你的文件、已连接的服务，以及工作之间的上下文关系，拥有直接且持续的访问能力。

📁

不再是"上传文件"

授权哪些文件夹由你决定，Quick 可以直接读、写、搜索和索引，没有上传动作，也不受浏览器体积限制。

🔗

跨服务合并信息

连上邮件、日历、聊天、CRM 后，可以在一次对话里从多个服务取数、执行动作并交叉比对，不用来回切工具。

🧠

越用越懂你的上下文

逐步构建关于人、项目、决策的知识图谱，并把偏好与工作方式留在长期记忆里，回答因此带上你的工作背景。

⚠️
当前为 Preview。面向 Plus 与 Enterprise 账户，Free 账户可在前 30 天试用。桌面端与 Web 端共享核心 AI 能力，但 Preview 阶段两端的功能集并不完全对齐。
02 · Capabilities

能力底座

场景方案能不能跑通，取决于下面这些能力是否可用、权限是否够。这里按落地时的关注点重新组织，官方文档的原始编排见用户指南目录。

📁

本地文件访问

在 Settings → My computer 按文件夹授权。关键词搜索、语义搜索、知识图谱抽取三项可独立开关，互不影响。

🔌

连接器与 MCP

内置 Slack、Outlook、Teams、Gmail、Google Calendar、OneDrive 等 Web 连接器；MCP Server 支持 Local、Remote、从配置文件 Import 三种接法。

🧰

系统工具与权限

10 类内置工具，每类可设 Full Access / Read Only / Ask Each Time，还能按单个操作细化 —— 比如整体放开但对某个写操作要求逐次确认。

⚡

Skills

按需加载的自包含指令集。内置技能覆盖文档创建、网页浏览、图像生成、代码执行等，可整组开关；自建技能出现在 MY SKILLS 分组。

⏱️

定时任务与 Mission Control

把工作挂到周期任务上，在 Mission Control 统一看运行状态、待办输入、KPI 与历史产出，并可暂停或立即执行。

🤝

委派编码 Agent

通过 ACP 协议把开发类任务派给 Kiro 或 Claude Code，Quick 汇总结果回报，适合"分析在 Quick、改代码在 IDE"的分工。

🕸️

知识图谱与记忆

自动抽取人、客户、项目、事件、行动项等实体及关系，存在本地。在 Settings → My context 查看与配置，可按集成源和按文件夹分别开关抽取。

🎚️

响应模式

对话与定时任务都可选 Fast / Balanced / Smart（对话另有 Auto）。按任务复杂度在速度与质量之间取舍。

10 类内置系统工具

在 Settings → Capabilities → Tools 中逐项启停与配权限。

工具能做什么要留意的地方
🔍 Web Search联网检索并返回带引用的摘要，可抓取指定网页全文可在单次对话里临时开关
📄 File operations从 URL 下载文件；用系统默认应用打开本地文件两个操作都算写操作

✍️ Engram Builder分析你的写作风格并存成 engram，之后用你的语气产出内容适合起草邮件、消息与文档

Full Access

读写全开，操作不再逐次征询确认。

Read Only

只读，不能通过该工具修改、写入或删除数据。

Ask Each Time

每次操作前都要你确认，适合写操作与敏感数据。

界面速览

左侧边栏做导航，顶栏切换浮层面板，中间是主内容区。知道东西在哪，配置和排查都会快很多。

位置内容
侧边栏 · 主导航New chat（开新对话）、Activity feed（统一优先级信息流）、My stuff（产物库）、Agents & skills（技能与代理管理）、More（Apps / Chat agents / Research / Flows / Spaces / Dashboards，在 Web 端打开）
侧边栏 · Recents按日期组织的历史对话，可建文件夹、置顶、删除，并支持跨对话与产物搜索
侧边栏 · SettingsCapabilities（连接器 / 计划 / 工具）、My computer（本地文件权限与索引）、My context（知识图谱与记忆）、Customization（外观、通知、浏览器、语音等）
顶栏面板Feed（信息流浮层）、Mission Control（后台任务与代理活动）、All data and apps（已连接数据源状态）
Home随时段变化的问候语、聊天输入区（角色选择 / 附件 / 响应模式 / 语音）、未连接数据源的引导卡、优先事项组件

04 · Skills

Skills 机制

Skill 是把一套工作方法固化下来的载体 —— 这也是 Playbook 里所有场景方案的交付形式。理解它的结构，才能把自己的业务流程沉淀成可复用资产。

📋

Instructions

一份 SKILL.md：多步工作流、每步的校验标准、失败时的降级路径。比提示词模板重得多。

🔧

Tools

技能可声明要带的工具。技能激活时，这些工具自动载入当前会话。

📎

Reference files

执行期可访问的脚本、模板、配置等支撑文件。

三种创建方式

在 Agents & skills → Skills → + Create 下：

Create with AI —— 描述你要什么，Quick 生成指令、挑工具、写出 SKILL.md，你再审阅修改。

Import from file —— 直接导入现成的 SKILL.md。

顺手沉淀 —— 多步任务成功完成后，Quick 可能主动提议把这个流程存成技能。

三种调用方式

点名 —— 在对话里提技能名，例如"用网页浏览技能看下这一页"。

自动识别 —— Quick 判断请求与某技能相关就自动加载，比如你要做 PPT 时演示文稿技能会自己上。

Run 按钮 —— 在 Skills 列表选中技能点 Run，直接开一个已载入该技能的会话。

💡
写技能的关键取舍：把确定性计算（指标、匹配、图表）下沉到脚本，只把判断类工作（字段映射确认、建议生成、异常升级）留给模型。这样产出的数字可复现、可审计，同时保留 AI 的解释能力。本 Playbook 的场景方案都按这个原则组织。
